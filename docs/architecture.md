# Advanced EXIF Frame — 설계와 검증

## 경계

- `domain`: 사진·편집 레시피·설정 계약. React와 브라우저 저장소에 접근하지 않습니다.
- `engine`: 프레임 painter, 좌표 계산, EXIF 정규화, 픽셀 렌더링. 설정을 인자로 받으며 localStorage나 애플리케이션 상태에 접근하지 않습니다.
- `application`: 이미지 읽기·내보내기, 레시피 스냅샷, JSON 검증, 환경설정과 세션 상태.
- `ui`: React 작업 공간, 도구 패널, 접근 가능한 공통 컨트롤, 포인터·키보드 크롭 조작.

기존 프로젝트는 읽기 전용 참조로 사용했습니다. Konsta UI·라우팅·전역 저장소·Capacitor 경로를 복사하지 않았습니다. 프레임 수식, 크롭·회전·비율 계산과 EXIF 바이트 정규화는 출력 호환성을 위해 엔진으로 이식했습니다. 폰트·로고·샘플 사진·기존 번역과 옵션 데이터도 유지했습니다. 기존 코드 전체를 복제해 UI만 교체한 구조가 아닙니다.

## 데이터와 출력

원본 `File`·디코딩한 이미지·원본 데이터 URL을 사진 레코드가 유지합니다. 편집 결과는 회전과 정규화 좌표 레시피로만 저장합니다. 썸네일과 미리보기는 별도이며 출력의 소스로 사용하지 않습니다. Undo/redo도 원본을 재인코딩하지 않고 레시피를 바꿉니다.

미리보기와 출력은 동일한 렌더러를 사용합니다. 미리보기만 마지막 표시 단계에서 최대 1600px로 축소합니다. 내보내기는 시작 시 전체 설정과 사진 레시피를 복제하고, 최종 결과를 원본에서 그립니다. PNG/native 경로는 강제 축소를 우회합니다. 프레임 전체 비율 적용, EXIF 영역 크기, 최종 비율 계산도 공통 엔진에서 처리합니다.

PNG는 디코딩된 픽셀 기준 무손실이며 원본 바이트 보존 포맷은 아닙니다. JPEG 100은 원본 해상도를 유지하지만 손실 재압축입니다. 임의 각도에는 보간이 필요합니다. 고비트 심도·ICC/색상 관리·매우 큰 Canvas 제한은 브라우저에 따릅니다. WebP EXIF 삽입은 기존과 동일하게 제공하지 않습니다. HEIC/TIFF는 브라우저가 디코딩할 수 있을 때 가져옵니다. 개별 파일 가져오기 한도는 250MB입니다.

## 저장

- `advanced-exif-frame.preferences.v1`: 테마, 내보내기, 표시·언어·외관과 메타데이터 프리셋.
- `advanced-exif-frame.collage.v1`: 콜라주 배치 환경설정.
- 사진, 사진별 레시피·배경·메타데이터, undo/redo, 콜라주 사진 선택은 세션에만 존재합니다.
- 원본 파일은 수정하지 않습니다. 이전 앱의 저장소 키를 읽거나 덮어쓰지 않습니다.
- 기존 전체/사진별 JSON의 `format`·`version`과 필드명을 유지합니다. 개별 사진 JSON은 원본 크기가 일치해야 하며 원본 파일은 포함하지 않습니다.

## 최적화와 수정

- 변경이 연속으로 들어오는 미리보기는 debounce하고 이전 작업은 전체 Canvas 할당 전에 취소합니다.
- 로고는 해당 제조사만 불러오며, 폰트와 로고 로딩을 캐시합니다. 폰트도 자체 호스팅합니다.
- 일괄 출력은 동시에 거대한 Canvas를 여러 개 만들지 않고 순서대로 처리합니다. 임시 Canvas는 사용 후 해제합니다.
- 사진 배경·메타데이터 변경 때 썸네일을 불필요하게 다시 그리지 않습니다.
- 기존 카메라·렌즈 덮어쓰기 필드가 실제 출력에 적용되지 않던 문제를 명시적 메타데이터 해석으로 수정했습니다.
- 메타데이터가 없는 정상 사진도 가져올 수 있습니다.
- 개발 서버에서 WebP WASM 주소를 잘못 찾는 문제를 명시적 자산 URL로 해결했습니다.
- 크롭 화면 크기 계산에 패딩을 제외해 실제 이미지와 선택 좌표가 일치하도록 했습니다. 크롭 키보드 이동은 사진 전환 단축키와 충돌하지 않습니다.
- 모달은 native dialog의 포커스 관리와 Escape 동작을 사용합니다. 숨긴 체크박스가 패널 밖 페이지 스크롤을 만드는 문제도 수정했습니다.

## 검증 범위

- 엔진·상태 검사: 2,000개 결정적 회전/크롭 조합, 모든 하단 테마와 비율·크기, 16색 대비, 원본 불변, 프리뷰/PNG 픽셀 일치, 5003px 원본 해상도 보존, JPEG/WebP 디코딩, JSON 검증과 저장 범위.
- EXIF 검사: 8개 orientation × TIFF의 두 바이트 순서 × JPEG/PNG. 출력 orientation 1·실제 크기·썸네일 제거·압축 데이터 보존과 PNG 디코딩을 확인합니다.
- 기존 엔진 비교: 16개 프레임 × 기본/편집/EXIF 크기 3조건 = 48개 픽셀 비교, 콜라주 3개 비율의 픽셀 비교.
- 브라우저: 데스크톱·390px 모바일 화면, 가져오기·선택·크롭·배경·품질 비활성화·ZIP와 동봉 JSON·모달, 실제 WebP WASM 출력, 설정 재시작/JSON 복원, Shift와 키보드·최종 비율 연계.
- TypeScript·ESLint·Prettier 및 프로덕션 빌드.

기존 엔진 비교는 동일한 Node Canvas 환경에서 수행하는 수식/픽셀 회귀 검사입니다. 모든 브라우저·OS의 글꼴 래스터화와 색상 관리까지 동일하다고 보장하는 검사는 아닙니다. 기존 프로젝트가 없는 CI에서는 이 비교만 건너뛰고 독립 엔진·상태·브라우저 검사를 실행합니다. 실제 Cloudflare 배포는 수행하지 않았습니다.

## 확장

새 프레임은 `engine/themes/painters`의 순수 painter와 옵션 선언을 추가한 뒤 카탈로그에 등록합니다. UI는 그 옵션 선언에서 컨트롤을 생성합니다. 새 편집 기능은 원본을 바꾸지 않는 레시피 필드를 정의하고 좌표/렌더러·JSON 검증·히스토리·출력 경로를 함께 확장합니다. UI에 별도 이미지 합성 로직을 만들지 않는 것이 기준입니다.
